# 01 — 原理与架构

封号通常不是因为用得太狠，而是环境前后对不上。风控眼里的问题：

| 问题 | 表现 |
|---|---|
| 出口是机房 IP | 服务器 IP 段被标成数据中心，不像普通用户 |
| 出口老在变 | 今天这个 IP 明天那个，会话对不上 |
| 代理挂了偷偷回退 | 代理一断，流量切回原始机房 IP，等于自己把环境变了 |
| 登录请求从本地发出 | 邮件图片、登录链接由本地浏览器发请求，暴露真实环境 |
| 多账号 Cookie 混在一起 | 几个号在同一浏览器轮换，登录态互相污染 |

这套方法就是把所有会暴露真实环境的环节，搬进一个固定的美国住宅网络。

## 链路

```text
本地电脑 → 美国 AWS 服务器 → 美国静态住宅 IP → Claude
远程操作     登录/授权/使用      固定出口
```

相当于在美国放一台专门用 Claude 的电脑，人坐在自己电脑前操作它。Claude 看到的始终是一台美国住宅网络里的普通电脑。

## 三部分，缺一不可

1. **一台美国 AWS 服务器**——把使用环境整体搬过去。
2. **一个固定的美国静态住宅 IP**——给这台服务器一个真实稳定的出口。注意是住宅代理的固定出口，不是 AWS 控制台里的静态公网 IP，后者是机房 IP，正是要避开的。
3. **断网保护**——所有业务联网都走住宅代理；代理断开、超时或重启时断网，不回退到服务器原始 IP。保留 SSH 管理通道，重启后规则仍生效。

只换 IP 不够：本地环境、登录请求、浏览器还留在原地。
只上服务器不够：服务器默认出口是机房 IP，一眼能认出来。
不做断网保护等于没做：代理总会断，那一刻切回机房 IP，前面全白费。

## 多账号

单台服务器 + 单个住宅 IP 可以挂多个 Pro 账号：

- 每个号一个独立的 Chrome 用户配置，隔离 Cookie 和登录态。注意只隔离登录态，不分配独立出口。
- 用 tmux 建 `claude-a` / `claude-b` 切换入口：凭证各自独立保存，项目代码、CLAUDE.md、任务进度、交接记录共用一份。
- A 号把进度、代码改动、下一步写进共享交接文件，B 号读文件接着干。

账号上限没有验证过，别默认更多号也安全。多个会话不能同时改同一份代码。

## 记忆备份

号万一被封，会话和记忆可能一起没。把 memory、readable、sessions、tools、项目代码、交接脚本定时备份到 GitHub，号没了记忆还在，能迁到新号。这一步没有副作用，单独做也值。
