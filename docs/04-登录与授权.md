# 04 — 登录与授权（第二步）

> 目标：把"登录"这个动作本身也放进服务器环境，不让任何登录请求从本地发出。

## 装远程桌面和 Chrome

让 Codex 给服务器安装远程桌面和 Chrome，并通过 SSH 隧道连接远程桌面。连上之后，等同于在操作另一台电脑。

## 在服务器里完成登录

1. 打开服务器内的 Chrome，完成 Claude 登录以及 Claude Code 授权。
2. **关联使用的邮箱，也在服务器浏览器内登录**。收邮件、打开登录链接全部在这个环境完成。
3. 原因：邮件里的图片、链接会产生网络请求；登录链接点开之后，网络请求是由当前打开的浏览器发出的。如果邮箱在本地登，请求就从本地真实环境发出，前面搬服务器的努力就破功了。

## 多账号：Cookie 隔离

登录多个账号，必须创建**独立的 Chrome 用户配置文件**：

- A 账号一套 Chrome 用户，B 账号另外一套。
- 让 Codex 生成对应的桌面快捷方式，避免登录 Cookie、会话状态互相混淆。

⚠️ 说明：这一步**只隔离登录状态 Cookie，不会为不同账号分配独立网络出口**。所有账号仍然共用同一个服务器、同一个住宅 IP。

## 检查点

- [ ] Claude 登录和 Claude Code 授权都在服务器浏览器完成。
- [ ] 关联邮箱在服务器浏览器登录，登录链接在服务器环境点开。
- [ ] 多账号各有独立 Chrome 用户配置 + 桌面快捷方式。
- [ ] 登录阶段没有在本地浏览器留下任何 Claude 登录请求。
