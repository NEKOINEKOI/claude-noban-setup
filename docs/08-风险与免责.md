# 08 — 风险与免责

> 这篇必须读。方案不是万无一失，风险如实列在这里。

## 免责声明（原文）

> 本篇仅为个人使用思路以及有限条件下的实测，不代表照搬这套方案就一定不会封号。

作者原话：自己也一直用 Claude Code，被封过 10 多次；这套方案搭建完成后目前几个月没出问题。并明确"跟你自己的网络环境、账号哪来的都有关系，不确保不封，只是一次知识教学"。

## 风险清单

| 风险 | 等级 | 说明 |
|---|---|---|
| 仍可能封号 | 高 | 作者实测稳定 ≠ 保证。平台风控策略随时会变。 |
| KYC 成品号来源 | 高 | 违反服务条款、可能被找回、来源不明、资金风险。这是灰产环节。 |
| 住宅 IP 连坐 | 高 | 买到之前被封过的 IP，新号直接跟着死。买 IP 看运气。 |
| 违反服务条款 | 中高 | 多账号、代理规避可能违反 Claude 使用条款，账号资产不受保护。 |
| 代理断网影响使用 | 中 | 保护生效时代理一挂就断网，直到恢复。设计如此。 |
| 多账号关联 | 中 | 独立 Chrome 配置只隔离 Cookie，不隔离出口；所有号仍共用一个 IP。 |
| 多会话改代码冲突 | 中 | 交接文件是串行的，多个会话同时改同一份代码会乱。 |
| 配置复杂度 | 中 | DNS 接管、IPv6/UDP 阻断、重启保持，配错一处就泄漏真实出口。 |
| 记忆泄露 | 中 | 备份到 GitHub 若用公开仓库会泄露敏感信息，必须用私有仓库。 |

## 边界条件（作者没说的，别当已知）

- 没测过账号上限——3 个稳定不代表 10 个也稳定。
- 没验证"用满一个月就绝对安全"——作者明确说不代表。
- "AWS 在白名单"是作者个人猜想，无确切信息源，别当事实用。
- 只在作者自己的网络环境和账号来源下实测过，换环境结果未知。

## 建议的最低安全做法

1. **先单账号**：跑一个月，确认出口和断网保护生效，再加号。
2. **记忆先备份**：这是纯赚的一步，从第一天就做，且用私有仓库。
3. **短买 IP 先测**：验证纯净度和归属再包月，别赌运气。
4. **能走官方渠道就走官方**：所在地能正常用官方订阅或 API，就别折腾这套。

## 一句话

这套方案降低封号概率，不归零；它解决的是"当地用不了、又确实需要"的问题，不是"保证不封"的银弹。自己权衡。
