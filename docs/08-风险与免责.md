# 08 — 风险与免责

## 免责

同好之间分享的方法整理，不保证效果。能不能成取决于账号来源、网络环境和使用方式。禁止商用。

## 风险清单

| 风险 | 等级 | 说明 |
|---|---|---|
| 仍可能封号 | 高 | 不保证不封，平台风控策略随时会变。 |
| 成品号来源 | 高 | 可能违反服务条款、可能被找回、来源不明、资金风险。 |
| 住宅 IP 连坐 | 高 | 买到之前被封过的 IP，新号直接跟着死，这是最大的隐性成本。 |
| 违反服务条款 | 中高 | 多账号、代理规避可能违反 Claude 使用条款，账号资产不受保护。 |
| 代理断网影响使用 | 中 | 保护生效时代理一挂就断网，直到恢复，这是设计如此。 |
| 多账号关联 | 中 | 独立 Chrome 配置只隔离 Cookie，所有号仍共用一个出口。 |
| 改代码冲突 | 中 | 多个会话同时改同一份代码会乱。 |
| 配置复杂度 | 中 | DNS 接管、IPv6/UDP 阻断、重启保持，配错一处就泄漏真实出口。 |
| 记忆泄露 | 中 | 备份到公开仓库会泄露敏感信息，必须用私有仓库。 |

## 边界条件

- 账号上限没有验证过，3 个能跑不代表更多也安全。
- 用满一个月不代表后面绝对安全。
- "AWS 在白名单"没有确切信息源，不要当事实用。
- 只在特定网络环境和账号来源下整理过，换环境结果未知。

## 最低安全做法

1. 先单账号跑一个月，确认出口和断网保护生效，再加号。
2. 记忆先备份，用私有仓库。
3. 住宅 IP 先短买测试，验证纯净度和归属，别赌运气。
4. 能走官方渠道就走官方，官方订阅和 API 的合规风险和折腾成本都低得多。

## 一句话

这套方法降低封号概率，不归零。它解决的是当地用不了、又确实需要的问题，不是保证不封的银弹。
