# 03 — 搭建服务器环境（第一步）

> 这一步的目标是：让服务器上所有业务联网都走固定住宅出口，且代理挂了就断网，绝不回退。

## 交给 Codex 的指令

把下面这段完整告知 Codex，让它通过 SSH 连接服务器后落实。可直接复制 `prompts/codex-setup-prompt.md`。

> 帮我搭建一个固定出口的 Claude 使用环境。服务器上所有业务联网，包括 Claude Code、浏览器和后台程序，都必须走指定的静态住宅 IP。住宅代理断开、超时或者重启时，宁可断网，也不能切回服务器原始 IP。保留必要的 SSH 管理通道，并验证保护规则在服务器重启后仍然有效。

## 配置完成校验清单（逐条核对，缺一不可）

- [ ] Claude Code、浏览器及后台程序统一走住宅代理，**不退回原始 IP**。
- [ ] 代理断开、超时或重启时，业务**断网**（不是回退，不是继续用原始 IP）。
- [ ] DNS 接管，IPv6 和其他 UDP 直连阻断（防止绕过代理泄漏真实出口）。
- [ ] 多次整机重启后，保护策略依旧生效，SSH 管理通道保留。
- [ ] 断开代理做一次实测：确认业务真的断了，而不是悄悄切回原始 IP。

> 这是整套方案最重要的一步：**宁可断网，也绝不换出口**。校验不过就不要进入下一步。

## 配置完成后

1. 打开远程桌面，在服务器内置浏览器登录 Claude。
2. **账号尚未登录阶段，不要做实际对话测试**——避免未登录状态下产生异常请求。
3. 后续重连使用启动脚本（不要手动临时改网络设置，那样会绕过保护规则）。

## 常见失败信号

| 现象 | 判断 |
|---|---|
| 代理断了之后 Claude 还能用 | 配置失败——流量切回了原始 IP，必须重做断网保护 |
| 浏览器显示 IP 是机房 ASN | 住宅代理没接管，或买到了假住宅 IP |
| 重启后保护失效 | 规则没写进开机自启，要求 Codex 修正 |
| SSH 也断了 | 管理通道没保留，要求 Codex 单独放行 SSH |
