# Claude 不封号，亚马逊云方案，抓紧看，可能随时没了

提示：本文有可能随时被删除，请抓紧阅读。

我已经跟刘容沟通过，她说会删帖，但我已经给圈友们说了有方案，完全不拿出来好像也有点问题。那就发出来，大家抓紧看，看看有没有帮助。

我自己一直在用 Claude Code，但也已经被封了 10 多次了，这套方案搭建完成之后，目前已经几个月没出现封号问题。

另外，点赞评论大家安排上吧，不要做伸手党，对所有给破局创造内容、项目、思路、商业的 KOL 都应该这样，这样才是一个良性的、正向的圈子。

好了，回归正题：

很多圈友用 Claude，最头疼的就是账号用着用着，突然被封了。

我们也折腾过不同的环境。目前这套方案，同一台服务器、同一个静态住宅 IP，跑了 3 个 Pro 账号，截至现在都还正常。

今天把思路拆开讲给大家。具体的安装配置，可以交给 Codex 去做。

简单点说就是：把 Claude 的登录、授权、日常使用，全部搬到美国的亚马逊云服务器上，再给它配一个固定的美国住宅 IP。本地电脑负责远程操作。

你可以理解为，在美国放了一台专门使用 Claude 的电脑，我们坐在自己的电脑前操作它。

整条链路很简单：本地电脑 → 美国 AWS 服务器 → 美国静态住宅 IP → Claude。

## 我为什么选亚马逊云

1. 亚马逊和 Anthropic 确实有合作，AWS 本身也通过 Amazon Bedrock 提供官方 Claude 模型 API 服务，有官方资料可查。
2. 个人实测经历：之前也注册过其他厂商的服务器，用同一套思路搭环境。第一天正常，第二天账号就被封了。换到这套亚马逊云方案后，目前多个账号都还在正常使用。

猜测：亚马逊或许在某种白名单内，仅为个人猜想，无确切信息源。

## 需要准备四样东西

1. 一台美区亚马逊云服务器。
2. 一个美国静态住宅 IP。建议尽量和服务器在同一地理区域，例如都在美国西部，先把链路跑稳。注意：这里指住宅代理的固定出口，不是 AWS 控制台里面的静态公网 IP。风险提示：购买静态 IP 要看运气，如果买到之前已经封号的 IP，新账号也会被连坐封号。
3. 一个能用的 Codex。让它通过 SSH 帮我们搭环境、检查代理、验证断网保护。你负责说清要求，它负责落实配置。
4. Claude Pro 账号。需要购买已经完成 KYC 验证的成品号，目前充值 Pro 也必须完成 KYC 验证。建议先从一个账号开始，有实际需要再增加。优先使用 Pro，观察一个月，再根据用量考虑 Max，控制前期投入。使用满一个月也不代表后续绝对安全。账号不够可以使用多个 Pro，不必急于开 Max，记忆可以共享，不用担心换号麻烦。

## 第一步，让 Codex 把服务器环境搭好

让 Codex 通过 SSH 连接服务器，把下面这条要求完整告知：

> 帮我搭建一个固定出口的 Claude 使用环境。服务器上所有业务联网，包括 Claude Code、浏览器和后台程序，都必须走指定的静态住宅 IP。住宅代理断开、超时或者重启时，宁可断网，也不能切回服务器原始 IP。保留必要的 SSH 管理通道，并验证保护规则在服务器重启后仍然有效。

✅ 整套方案最重要核心：宁可断网，也绝不换出口。

配置完成校验要点：

- Claude Code、浏览器及后台程序统一走住宅代理，不退回原始 IP。
- 代理断开、超时或重启时，业务断网。
- DNS 接管，IPv6 和其他 UDP 直连阻断。
- 多次整机重启后保护策略依旧生效，SSH 管理通道保留。

配置完成后打开远程桌面，在服务器内置浏览器登录 Claude，账号尚未登录阶段，不要做实际对话测试。后续重连使用启动脚本。

## 第二步，把登录过程也放到服务器上

让 Codex 给服务器安装远程桌面和 Chrome，并通过 SSH 隧道连接远程桌面。

连接之后，等同于操作另一台电脑，打开服务器内的 Chrome，完成 Claude 登录以及 Claude Code 授权。

实操建议：关联使用的邮箱，也在服务器浏览器内登录。收邮件、打开登录链接全部在该环境完成。

原因：邮件里的图片、链接会产生网络请求，登录链接点开之后，网络请求由当前打开的浏览器发出。

多账号注意事项：登录多个账号，必须创建独立的 Chrome 用户配置文件。A 账号一套 Chrome 用户，B 账号另外一套，让 Codex 生成对应的桌面快捷方式，避免登录 Cookie、会话状态互相混淆。

说明：该操作只隔离登录状态 Cookie，不会为不同账号分配独立网络出口。

## 多个账号，如何接续同一个任务

多账号场景希望切换账号可以接续任务进度，可以搭配 tmux 搭建切换入口。例如输入 claude-a 进入 A 账号环境；输入 claude-b 进入 B 账号环境。

两件事需要区分：

1. 账号登录凭证互相独立保存。
2. 项目资料、工作记忆做共享。

多个环境共用同一份项目代码、CLAUDE.md、任务进度、交接记录。A 账号完成进度、代码修改内容、下一步计划，全部写入共享交接文件；切换到 B 账号之后，读取交接记录继续开展工作。

- tmux 负责维持终端会话；共享文件负责任务交接。
- 不会自动合并各个账号完整聊天历史；禁止多个会话同时修改同一份代码。

实测情况：单台服务器、同一个静态住宅 IP，稳定运行 3 个 Pro 账号。没有测试账号上限；3 个账号稳定，不代表更多账号就一定安全。

建议流程：先用单个账号搭建环境，确认网络出口、断网保护完全生效，再考虑增加账号投入。

## 将记忆备份上传到 GitHub（非常重要）

可以让 Claude 协助实现记忆上传 GitHub，提供 GitHub 凭据即可。设置定时更新上传记忆备份。

作用：就算账号被封禁，记忆数据保存在 GitHub，可以无缝迁移到其他 Claude 账号。即使这套服务器方案后续出现封号，记忆数据也可以留存。

备份目录一般包含：memory、readable、sessions、tools、工作空间代码、各类交接脚本与文档。
