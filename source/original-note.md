# 方法整理

把 Claude 的登录、授权、日常使用全部搬到美国的亚马逊云服务器上，配一个固定的美国住宅 IP。本地电脑只负责远程操作。

链路：本地电脑 → 美国 AWS 服务器 → 美国静态住宅 IP → Claude。

相当于在美国放一台专门用 Claude 的电脑，人坐在自己电脑前操作它。

## 为什么选亚马逊云

- 亚马逊与 Anthropic 有合作，AWS 通过 Amazon Bedrock 提供官方 Claude 模型 API，有公开资料可查。
- 同样的思路换其他厂商服务器，环境不稳；换到 AWS 后多个账号能持续正常。
- "AWS 在白名单"的说法没有确切信息源，不要当事实用。

## 准备四样东西

1. 一台美区亚马逊云服务器。
2. 一个美国静态住宅 IP。尽量和服务器在同一区域（如都在美国西部），先把链路跑稳。这里指住宅代理的固定出口，不是 AWS 控制台里的静态公网 IP。注意：买到之前被封过的 IP，新号会被连坐。
3. 一个能用的 Codex。通过 SSH 搭环境、检查代理、验证断网保护。说清要求，它负责落实配置。
4. Claude Pro 账号。充值 Pro 需要完成 KYC。先从一个号开始，有需要再加；优先 Pro，观察一个月再考虑 Max，控制前期投入。号不够用多个 Pro，记忆可以共享，不必急开 Max。用满一个月也不代表后面绝对安全。

## 第一步：搭服务器环境

让 Codex 通过 SSH 连接服务器，把下面这条完整告知：

> 帮我搭建一个固定出口的 Claude 使用环境。服务器上所有业务联网，包括 Claude Code、浏览器和后台程序，都必须走指定的静态住宅 IP。住宅代理断开、超时或者重启时，宁可断网，也不能切回服务器原始 IP。保留必要的 SSH 管理通道，并验证保护规则在服务器重启后仍然有效。

核心：宁可断网，也绝不换出口。

配置完成校验：

- Claude Code、浏览器及后台程序统一走住宅代理，不退回原始 IP。
- 代理断开、超时或重启时，业务断网。
- DNS 接管，IPv6 和其他 UDP 直连阻断。
- 多次整机重启后保护策略依旧生效，SSH 管理通道保留。

配置完成后打开远程桌面，在服务器内置浏览器登录 Claude。账号尚未登录阶段不要做对话测试。后续重连用启动脚本。

## 第二步：把登录过程也放到服务器

让 Codex 装远程桌面和 Chrome，通过 SSH 隧道连接。连上后等同于操作另一台电脑，在服务器内的 Chrome 完成 Claude 登录和 Claude Code 授权。

关联使用的邮箱也在服务器浏览器内登录，收邮件、点登录链接都在该环境完成。原因：邮件里的图片、链接会产生网络请求，登录链接点开后请求由当前浏览器发出。

多账号：必须建独立的 Chrome 用户配置文件。A 号一套，B 号一套，让 Codex 生成对应的桌面快捷方式，避免 Cookie 和会话混淆。这一步只隔离登录状态 Cookie，不为不同账号分配独立出口。

## 多账号如何接续同一个任务

用 tmux 搭切换入口，例如输入 `claude-a` 进 A 号环境，输入 `claude-b` 进 B 号环境。

两件事要分开：

1. 账号登录凭证互相独立保存。
2. 项目资料、工作记忆共享。

多个环境共用同一份项目代码、CLAUDE.md、任务进度、交接记录。A 号把完成进度、代码改动、下一步计划写进共享交接文件；切到 B 号后读交接文件接着干。

- tmux 负责维持终端会话，共享文件负责任务交接。
- 不会自动合并各账号完整聊天历史；禁止多个会话同时修改同一份代码。

账号上限没有验证过，别默认更多号也安全。建议先单账号把出口和断网保护跑通，再考虑加号。

## 把记忆备份上传到 GitHub

让 Claude 协助把记忆上传 GitHub，提供凭据即可，设置定时更新。

作用：号被封禁后记忆数据仍在 GitHub，能无缝迁到其他账号。即使这套服务器方案出问题，记忆也能留存。

备份目录一般包含：memory、readable、sessions、tools、工作空间代码、各类交接脚本与文档。
